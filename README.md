# トレーニングログ(スタンドアロン版)

Claudeを介さずに、ブラウザ単体で動くトレーニング・体重・食事の記録アプリです。
データは端末の localStorage に保存され、Google Sheets連携を設定すると、変更をまとめて(2.5秒デバウンス)自動でスプレッドシートにも書き込まれます。
Claude の API は一切呼び出さないため、利用枠(usage)は消費しません。
基本機能(運動・体重・食事の記録、カロリー収支、内蔵の食品辞書など)はすべてルールベースで完結し、外部通信は発生しません。
**唯一の例外**が、任意で使える「🔍 AIで栄養を調べる」機能と「🤖 AIのひとこと」機能です。これらだけは設定した場合に限り、Google Gemini APIに食品名や直近の記録を送って概算・コメントを取得します(詳しくは後述)。使わなければ今まで通り完全オフラインで動作します。

## 今回の更新内容 [v17](改善: Gemini混雑時に別のモデルへ自動で切り替え)

- 「🤖 AIにコメントをもらう」で HTTP 503(混雑)が続く件に対応しました。v11で自動リトライを入れましたが、**同じモデルが混み続けている場合は、何回試しても同じように混んでいる**ため、リトライだけでは足りませんでした。
- **混雑しているときに、別のモデルへ自動で切り替えるようにしました。** `gemini-3.7-flash`(本命)→ `gemini-3.6-flash` → `gemini-2.5-flash` の順に試します。人気の最新モデルほど混みやすいので、1つ前の世代に切り替えると通ることが多くなります。いずれも無料枠の対象です。
  - 503(混雑)・429(レート超過)・500番台に加えて、**404(モデルの廃止)でも自動的に次のモデルへ切り替わります。** 今後Googleがモデルを入れ替えても、AI機能が突然使えなくなりにくくなりました。
  - 一方、400(APIキーが不正)や403(権限なし)は、モデルを変えても直らないので、無駄に待たずすぐエラーを返します。
  - Apps Scriptの実行時間上限で「応答なし」にならないよう、全体で約25秒の締め切りを設けています。

### ⚠️ エラー文言について

いただいたエラーは `Gemini APIエラー (HTTP 503): {...}` という生のメッセージのままでした。v11以降のindex.htmlであれば、ここは「Google側が一時的に混雑しています。しばらく待ってからもう一度お試しください(設定に問題はありません)」という案内に変わります。**GitHubのindex.htmlが古いバージョンのままになっている可能性があります**ので、設定タブ一番下のバージョン表示をご確認ください(このzipは v17 です)。

**この更新はapps-script.gsとindex.htmlの両方を含みます。apps-script.gsを貼り直して「新しいバージョン」として再デプロイしてください**(APP_TOKEN・GEMINI_API_KEYの設定はそのままで大丈夫です)。

## 前回の更新内容 [v16](不具合修正: カロリー収支グラフが変化して見えない / 食事タブに日別の摂取・消費を表示)

### カロリー収支グラフの不具合を2件修正しました

ご指摘の通り、グラフはほとんど変化して見えない状態でした。原因は2つあり、どちらも実際の不具合でした。

- **①「記録のない日」がグラフの目盛りを決めてしまっていた**: 食事を記録していない日は「摂取0kcal」として扱われ、TDEE分まるごと(約2,300kcal)の巨大な赤字として計算されていました。グラフの縦の目盛りはその最大値に合わせられるため、実際に記録した日の棒(±500kcal程度)が数ピクセルまで潰れていました。実測では、1,800kcal記録した日の棒はわずか9.7ピクセル、そこに700kcal追加しても4ピクセルにしか変わらず、「更新されない」ように見えていました。**目盛りを「記録がある日」だけで決めるように修正**したので、以後は棒がしっかり伸び縮みします。
- **②カロリーを入れずに食事名だけ記録した日も、まるごと赤字として集計されていた**: 実際には食べているのに約2,300kcalの赤字として扱われ、グラフも平均アドバイスも大きく狂っていました。**そういう日は「不明」として扱う**ように修正し、グラフでは平らな線、下記の日別表示では「摂取 未入力」と表示されます。
- あわせて、グラフの右上に **「上端 ±○○kcal」という目盛りの数値**を表示するようにしました。棒の高さは記録内容に応じて自動で伸縮するため、この数値がないと「棒が伸びた=何kcal変わったのか」が読み取れなかったためです。

### 食事タブに、日ごとの摂取カロリーとTDEEを表示するようにしました

- 「📖 食事の履歴」の各日付の下に、**摂取 ○○kcal ／ 消費 ○○kcal(TDEE ○○ + 運動 ○○) → 赤字/黒字 ○○kcal** の1行を追加しました。
- 消費カロリーには、その日の運動による消費(概算)も加算され、内訳が見えるようになっています(運動を記録していない日はTDEEのみ)。
- ここに出る数値は、カロリー収支グラフとまったく同じ計算式を使っているので、両方の数字が食い違うことはありません。
- プロフィール・体重が未入力でTDEEを計算できない場合は、この行は表示されません。

## 前回の更新内容 [v11](改善: Gemini混雑時(503)の自動リトライと、エラー案内の正確化)

- 「Gemini APIエラー (HTTP 503) ... high demand」というエラーに対応しました。これはGoogle側が一時的に混雑しているという意味で、こちらの設定には問題がありません。
- **Apps Script側で自動リトライするようにしました**。混雑(503)・レート超過(429)・サーバーエラー(500番台)の場合、0.8秒→2秒→4秒と間隔を空けて最大3回まで自動で再試行します。一時的な混雑であれば、ボタンを押し直さなくてもそのまま成功するようになります。
- **エラー案内の文言を、原因ごとに出し分けるようにしました**。これまではどんなエラーでも一律に「Apps Script側のGEMINI_API_KEY設定をご確認ください」と表示していたため、今回の503のようにキー設定と全く無関係な場合でも、設定を疑わせてしまう誤った案内になっていました。今回から以下のように出し分けます。
  - 503(混雑) → 「Google側が一時的に混雑しています。しばらく待ってからお試しください(設定に問題はありません)」
  - 429(無料枠の上限) → 「無料枠の上限に達したようです。時間をおいてお試しください」
  - GEMINI_API_KEY未設定 → スクリプト プロパティの確認を案内
  - 404(モデル廃止) → GEMINI_MODELの更新を案内
  - 400(キーが不正) → APIキーの再確認を案内
- **この修正を反映するには、apps-script.gsを貼り直して再デプロイし、index.htmlも差し替えてください**(設定済みのAPP_TOKEN・GEMINI_API_KEYはそのままで大丈夫です)。

## 前回の更新内容 [v10](不具合修正: AI応答が「解釈できませんでした」になる問題に対応)

- 万が一また同様のエラーが出た場合に原因を特定しやすいよう、エラーメッセージにGeminiからの実際の応答(の一部)や、応答が空になった理由(`finishReason`)が含まれるようにしました。

## 前回の更新内容 [v8](大幅リニューアル: 接続情報の非公開化・シート分割・デバウンス同期・バックアップ復元・AIコメント)

### 主な変更点

- **Apps ScriptのURLをソースコードから削除**しました。これまではGitHubに公開されているindex.htmlに実際のURLが直書きされていたため、そのURLを知っている第三者なら誰でもシートに書き込めてしまう状態でした。今回から、URLとアクセストークン(合言葉)は「設定」タブから入力し、この端末のブラウザにのみ保存されます。Apps Script側もトークンが一致しないリクエストを拒否するようになりました。

- **同期をまとめて送るように変更**しました。記録するたびに毎回送信していたのを、2.5秒分の変更をまとめて1回で送るようにし、同時に走る同期を1本に制限しました。連続で記録したときに、あとから始まった通信が先に終わって古いデータで上書きしてしまう可能性を減らしています。画面を閉じる・バックグラウンドに回るときは、待機中の変更を取りこぼさず即座に送信します。
- **バックアップ・復元機能を追加**しました。「設定」→「データ」から、JSONファイルへの書き出し、JSONファイルからの復元、Googleスプレッドシートからの復元ができます。
- **「🤖 AIのひとこと」を追加**しました。直近2週間の記録をGoogle Gemini APIに渡して、コメントを生成してもらう機能です(ボタンを押したときだけ通信します。表示のたびに自動で呼ばれることはありません)。GEMINI_API_KEY未設定・取得失敗時は、これまで通りのルールベースのアドバイスに自動で切り替わります。

7. 念のため、6.の前に「設定」→「データ」→「JSONで書き出し」で一度バックアップを取っておくと安心です(この端末の記録は6.の保存時点で自動的に新しい形式のシートに書き直されます)。

- 同期は今も全件上書きです。まとめ送信と排他制御で事故は減りましたが、記録が数千行を超えるとApps Scriptの実行時間が影響してきます。

  - 「すべてのデータを削除」をすると、筋トレ種目はデフォルトのおすすめ内容に戻り、食事のマスタは空になります。
- **「運動」タブの種目チップがマスタ連動に**: 部位を選ぶと、その部位に登録されている種目がチップとして表示されます(未登録の部位はその旨が表示され、設定タブから追加できます)。記録の編集画面でも同じチップが使えます。
- **「食事」タブに「よく食べるもの」チップを追加**: マスタに登録した食事をタップすると、名前・カロリー・P/F/Cが記録フォームに自動入力されます(あとは日付を確認して「記録する」を押すだけ)。

## 前回の更新内容(UIを全面リニューアル)

別途プロトタイプ検討していた「AIダイエットアシスタント(ai-diet-mvp)」のUI・画面構成をベースに、こちらのアプリの機能(記録編集・カレンダー・部位別種目チップ・Google Sheets同期)をすべて統合しました。

- **タブ構成に変更**: 画面下部のタブバーで 今日 / 食事 / 体重 / 運動 / 設定 を切り替える形になりました。以前の「1ページに全部並ぶ」形式から、ai-diet-mvp式の画面構成になっています。
- **初回オンボーディング**: 初めて開いたとき(またはデータを全削除した後)に、年齢・性別・身長・体重・目標体重・運動習慣・使える時間・週間トレーニング目標を入力する簡単なウィザードが表示されます。既存のトレーニング・体重・食事の記録はそのまま引き継がれます。
- **「運動」タブ**: 歩数トラッキングの代わりに、筋トレ・有酸素の記録(部位別のおすすめ種目チップつき)・進捗グラフ(週間頻度・種目別重量推移)・履歴(リスト/カレンダー切り替え)をこのタブにまとめました。
- **「今日」タブ**: 連続記録日数、🤖 AIのひとこと(気分に応じたアドバイス+おすすめ運動、タップで運動タブに自動入力)、体重目標・週間トレーニング目標・今日のカロリーの達成状況をひと目で確認できます。
- **「設定」タブ**: Google Sheets同期状況、体重目標・週間トレーニング目標、AIアドバイス用プロフィール(年齢・身長・性別・運動習慣・使える時間、Mifflin-St Jeor式での目標カロリー・PFC計算)、データ削除をまとめています。
- 記録の編集(✏️)、部位ごとの種目チップ、Google Sheets同期・GitHub Pagesホスティングは変わらず利用できます。「食べ過ぎても怒らないAIチャット」は今回は含めていません。

## ファイル構成

- `index.html` … アプリ本体(このファイル1つだけで動作します)
- `apps-script.gs` … Googleスプレッドシートに書き込むための Google Apps Script コード
- `README.md` … このファイル

## セットアップ手順

### 1. 記録用のGoogleスプレッドシートを作る

1. [Google スプレッドシート](https://sheets.google.com) で新規シートを作成し、好きな名前を付ける(例:「トレーニングログ」)。
2. メニューから **拡張機能 → Apps Script** を開く。
3. デフォルトで入っているコードを全部消して、`apps-script.gs` の中身を貼り付けて保存する。
4. 画面右上の **デプロイ → 新しいデプロイ** をクリック。
5. 種類の選択で歯車アイコンから **ウェブアプリ** を選ぶ。
6. 設定:
   - 実行するユーザー: **自分**
   - アクセスできるユーザー: **全員**
7. **デプロイ** をクリックし、Googleアカウントでの承認を求められたら許可する。
8. 発行された **ウェブアプリのURL**(`https://script.google.com/macros/s/.../exec` の形式)をコピーしておく。

### 2. index.html にURLを設定する

`index.html` の冒頭付近にある以下の行を、手順1でコピーしたURLに書き換える。

```js
const GAS_URL = "PUT_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE";
```

### 3. ホスティングする(iPhoneのホーム画面に追加するため)

ローカルファイルのままだとiPhoneの「ホーム画面に追加」が安定しないため、どこかに公開してURLを持たせるのがおすすめです。手軽な方法をいくつか挙げます。

**GitHub Pages(無料・おすすめ)**
1. GitHubに新しいリポジトリを作る(例: `training-log`)。
2. このフォルダの `index.html` をリポジトリのルートに置いてpushする。
3. リポジトリの Settings → Pages で、公開元をそのブランチ(例: `main`)のルートに設定する。
4. 数分後、`https://<ユーザー名>.github.io/training-log/` のようなURLでアクセスできるようになる。

Claude Codeを使う場合、`git init` → `gh repo create` → `git push` → Pages設定、までを一通り自動化してもらうこともできます。

**Google Cloud Run**
すでにfreeeの自動化などでCloud Runを使っているなら、静的ファイル配信用のコンテナ(nginxなど)でこの `index.html` を配信することもできます。GitHub Pagesより一手間増えますが、他のインフラと管理を一本化したい場合はこちらでも構いません。

### 4. iPhoneのホーム画面に追加する

1. 公開したURLをiPhoneのSafariで開く。
2. 共有ボタン(□に↑のアイコン)をタップ。
3. 「ホーム画面に追加」を選択。

これでアイコンをタップするだけでフルスクリーンのアプリのように起動します。

## 動作の仕組み

- 記録の追加・削除のたびに、まず端末の localStorage に即座に保存します(ネット接続不要)。
- その直後にバックグラウンドで Apps Script の Web アプリ URL に記録全体を送信し、スプレッドシートの内容を丸ごと上書きします。
- 通信に失敗しても localStorage 側のデータは失われません。画面上部の同期ステータスをタップすると再試行できます。

## 既知の制限・カスタマイズ余地

- 現状、複数端末間でのデータ共有は「都度スプレッドシートに書き込む」一方向のみです(スプレッドシート側からアプリへの読み込みは未実装)。複数端末で使いたい場合は、起動時にスプレッドシートからデータを読み込む処理を追加すると良いです。
- ホーム画面用のアイコン画像(`apple-touch-icon`)は未設定です。好みの画像を用意して `<link rel="apple-touch-icon" href="icon.png">` をheadに追加すると、アイコンが見た目良くなります。
- デザイン(色・フォント)はai-diet-mvpのトーンに合わせています。調整したい場合は `<style>` 内のCSS変数(`--teal`, `--coral`, `--sand`, `--slate` など)を変更してください。
- AIによるアドバイス・目標カロリー計算はすべてルールベースの簡易ロジックで、外部AI APIには接続していません。医療的な正確性は保証されないため、実際の健康管理では専門家の助言も参考にしてください。
