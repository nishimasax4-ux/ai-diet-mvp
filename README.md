# トレーニングログ(スタンドアロン版)

Claudeを介さずに、ブラウザ単体で動くトレーニング・体重・食事の記録アプリです。
データは端末の localStorage に保存され、Google Sheets連携を設定すると、変更をまとめて(2.5秒デバウンス)自動でスプレッドシートにも書き込まれます。
Claude の API は一切呼び出さないため、利用枠(usage)は消費しません。
基本機能(運動・体重・食事の記録、カロリー収支、内蔵の食品辞書など)はすべてルールベースで完結し、外部通信は発生しません。
**唯一の例外**が、任意で使える「🔍 AIで栄養を調べる」機能と「🤖 AIのひとこと」機能です。これらだけは設定した場合に限り、Google Gemini APIに食品名や直近の記録を送って概算・コメントを取得します(詳しくは後述)。使わなければ今まで通り完全オフラインで動作します。

## 今回の更新内容 [v34](新機能: 食事タブの履歴に、日ごとのP/F/C合計と目標達成度を表示)

「過去の摂取状況がわからないので履歴も分かりやすく表示したい」とのご要望に対応しました。

**今回はindex.htmlのみの更新です。apps-script.gsの再デプロイは不要です**(表示だけの変更で、同期の仕組みやスプレッドシートの列構成には手を入れていません)。

## [v27](不具合修正: 消費カロリーで運動が二重に計上されていた問題)

「TDEEの計算は合っている?」とのご質問を受けて検算したところ、**運動が二重に計上されていました。** 計算式そのもの(Mifflin-St Jeor式のBMR、有酸素運動のMETs式)は正しかったのですが、組み合わせ方に誤りがありました。

### 何が間違っていたか

- これまでの消費カロリーは「**基礎代謝 × 運動習慣の係数**」で出していました。この係数(1.2〜1.725)は「週に何回運動するか」で決まる数字で、**その中にすでに運動ぶんが含まれています**(1.55は「週3〜5回運動する人」という意味の係数です)。
- ところがアプリは、そこに**さらにその日の運動の消費カロリーを上乗せ**していました。結果、運動が2回分カウントされていました。

40歳・170cm・75kg・男性の場合、1日あたりの過大分は次のとおりです。

| 運動習慣の設定 | 旧・消費カロリー | 過大だった分 |
|---|---|---|
| ほぼなし | 1941 | ±0 |
| 週1-2回 | 2224 | +283 |
| 週3-4回 | 2507 | **+566** |
| ほぼ毎日 | 2790 | **+849** |

「ほぼなし」を選んでいた場合だけは正しく、それ以外は消費を多く見積もっていました。**カロリー収支グラフの赤字が実際より大きく出ていた**ということで、記録上は減量できているはずなのに体重が減らない、という状態につながる箇所です。

### 変更した内容

- 消費カロリーの土台を「**基礎代謝 × 日常生活の活動量**」に変更しました。この係数には運動を含めません。運動ぶんは、これまでどおり**記録した内容から実測ぶんだけ**を上乗せします(「たくさん動いた日は多く食べてよい」という今までの考え方はそのままです)。
- 設定タブに「**日常生活の活動量(運動は除く)**」を追加しました。デスクワーク中心(×1.2) / よく歩く・立ち仕事(×1.35) / 力仕事が多い(×1.5)から選べます。**初期値はデスクワーク中心です。**仕事や家事でよく動く方は変更してください。
- 「運動習慣」の設定は残していますが、**消費カロリーの計算には使わなくなりました**(おすすめ運動の頻度とAIへの申し送りにのみ使います)。
- 画面上の「TDEE」という表記を「**基礎消費**」に変更しました。TDEEは本来「運動を含む1日の総消費」を指す言葉なので、運動を含まない土台の数字を指すには不正確だったためです。

### ⚠️ 目標カロリーが下がって見えます

この修正により、**1日の目標カロリーがこれまでより数百kcal低い数字になります。**これは目標が厳しくなったのではなく、**これまでが多すぎた**ためです。今までの数字を基準に食べていた場合、実際には想定ほどの赤字になっていなかった可能性があります。

過去に記録したデータはそのまま残り、グラフも新しい計算で描き直されます。

**今回はindex.htmlのみの更新です。apps-script.gsの再デプロイは不要です。**

## [v26](不具合修正: 「AIで栄養を調べる」がHTTP 400で失敗する問題 ＋ 失敗しても止まらない保険)

**※v25をお渡ししましたが、こちらのv26で置き換えてください。** v25の修正内容はすべて含んだうえで、「その修正が万一外れていても動く」ための保険を足したものです。

### v26で足したこと(保険)

上の原因の特定は、Googleの公式ドキュメントを調べたうえでの結論ですが、**手元から実際のGemini APIを叩いて確かめることができない**ため、100%の確証があるわけではありません。そこで「原因の推定が外れていても、AI機能自体は動く」ようにしました。

- **② 400が返ったら、「思考」の設定そのものを外して、そのモデルにもう一度だけ試すようにしました。** Googleは思考の指定方法を過去に変えてきた実績があるため(2.5系→3.x系)、また変わっても自力で復帰できます。

- あわせて、エラー案内が一律「APIキーが正しくない可能性があります」になっていた点を、原因ごとに出し分けるようにしました(今回のようにAPIキーと無関係な場合に紛らわしかったため)。

ご指摘の通り、グラフはほとんど変化して見えない状態でした。原因は2つあり、どちらも実際の不具合でした。

- **①「記録のない日」がグラフの目盛りを決めてしまっていた**: 食事を記録していない日は「摂取0kcal」として扱われ、TDEE分まるごと(約2,300kcal)の巨大な赤字として計算されていました。グラフの縦の目盛りはその最大値に合わせられるため、実際に記録した日の棒(±500kcal程度)が数ピクセルまで潰れていました。実測では、1,800kcal記録した日の棒はわずか9.7ピクセル、そこに700kcal追加しても4ピクセルにしか変わらず、「更新されない」ように見えていました。**目盛りを「記録がある日」だけで決めるように修正**したので、以後は棒がしっかり伸び縮みします。
- **②カロリーを入れずに食事名だけ記録した日も、まるごと赤字として集計されていた**: 実際には食べているのに約2,300kcalの赤字として扱われ、グラフも平均アドバイスも大きく狂っていました。**そういう日は「不明」として扱う**ように修正し、グラフでは平らな線、下記の日別表示では「摂取 未入力」と表示されます。
- あわせて、グラフの右上に **「上端 ±○○kcal」という目盛りの数値**を表示するようにしました。棒の高さは記録内容に応じて自動で伸縮するため、この数値がないと「棒が伸びた=何kcal変わったのか」が読み取れなかったためです。

### 食事タブに、日ごとの摂取カロリーとTDEEを表示するようにしました

- 「📖 食事の履歴」の各日付の下に、**摂取 ○○kcal ／ 消費 ○○kcal(TDEE ○○ + 運動 ○○) → 赤字/黒字 ○○kcal** の1行を追加しました。
- 消費カロリーには、その日の運動による消費(概算)も加算され、内訳が見えるようになっています(運動を記録していない日はTDEEのみ)。
- ここに出る数値は、カロリー収支グラフとまったく同じ計算式を使っているので、両方の数字が食い違うことはありません。
- プロフィール・体重が未入力でTDEEを計算できない場合は、この行は表示されません。

## セットアップ手順

### 1. 記録用のGoogleスプレッドシートを作る

1. [Google スプレッドシート](https://sheets.google.com) で新規シートを作成し、好きな名前を付ける(例:「トレーニングログ」)。
2. メニューから **拡張機能 → Apps Script** を開く。
3. デフォルトで入っているコードを全部消して、`apps-script.gs` の中身を貼り付けて保存する。
4. 画面右上の **デプロイ → 新しいデプロイ** をクリック。
5. 種類の選択で歯車アイコンから **ウェブアプリ** を選ぶ。
6. 設定:
   - 実行するユーザー: **自分**
   - アクセスできるユーザー: **全員**
7. **デプロイ** をクリックし、Googleアカウントでの承認を求められたら許可する。
8. 発行された **ウェブアプリのURL**(`https://script.google.com/macros/s/.../exec` の形式)をコピーしておく。

### 2. index.html にURLを設定する

`index.html` の冒頭付近にある以下の行を、手順1でコピーしたURLに書き換える。

```js
const GAS_URL = "PUT_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE";
```

### 3. ホスティングする(iPhoneのホーム画面に追加するため)

ローカルファイルのままだとiPhoneの「ホーム画面に追加」が安定しないため、どこかに公開してURLを持たせるのがおすすめです。手軽な方法をいくつか挙げます。

**GitHub Pages(無料・おすすめ)**
1. GitHubに新しいリポジトリを作る(例: `training-log`)。
2. このフォルダの `index.html` をリポジトリのルートに置いてpushする。
3. リポジトリの Settings → Pages で、公開元をそのブランチ(例: `main`)のルートに設定する。
4. 数分後、`https://<ユーザー名>.github.io/training-log/` のようなURLでアクセスできるようになる。

Claude Codeを使う場合、`git init` → `gh repo create` → `git push` → Pages設定、までを一通り自動化してもらうこともできます。

**Google Cloud Run**
すでにfreeeの自動化などでCloud Runを使っているなら、静的ファイル配信用のコンテナ(nginxなど)でこの `index.html` を配信することもできます。GitHub Pagesより一手間増えますが、他のインフラと管理を一本化したい場合はこちらでも構いません。

### 4. iPhoneのホーム画面に追加する

1. 公開したURLをiPhoneのSafariで開く。
2. 共有ボタン(□に↑のアイコン)をタップ。
3. 「ホーム画面に追加」を選択。

これでアイコンをタップするだけでフルスクリーンのアプリのように起動します。

## 動作の仕組み

- 記録の追加・削除のたびに、まず端末の localStorage に即座に保存します(ネット接続不要)。
- その直後にバックグラウンドで Apps Script の Web アプリ URL に記録全体を送信し、スプレッドシートの内容を丸ごと上書きします。
- 通信に失敗しても localStorage 側のデータは失われません。画面上部の同期ステータスをタップすると再試行できます。

## 既知の制限・カスタマイズ余地

このアプリは「サーバー側の仕組みを持たない、1人用の個人アプリ」として作られています。以下は、その設計から来ている既知の制限です。今の使い方(自分1人・基本1端末)では問題になりませんが、把握しておくと安心です。

### 同期は今も「全件上書き」です(v32で事故防止の警告を追加)

- 記録するたびに、その端末が持っている記録**全体**をスプレッドシートへ送って上書きする方式です。スプレッドシート側の1行だけを追記・更新する仕組みにはなっていません。
- **v32から、他の端末がこの端末の知らないうちに書き込んでいた場合は、自動では上書きせず警告するようになりました。** これは「データが消える事故」そのものを防ぐ機能ではなく、**事故が起きそうなときに気づけるようにする**軽量な安全策です(「設定」タブの同期カードに、上書きするか・シートから確認するかを選べる案内が出ます)。
- 本格的に複数端末(iPadと併用するなど)を常用する場合は、レコード単位でのマージ(どちらの変更も両方残す)までは対応していません。基本は「1端末で使い、たまに別端末から見るときは、必ず先に☁️シートから復元してから記録する」という運用が安全です。

### 同期トークンは平文でこの端末に保存されています

- 「設定」タブのトークン入力欄自体は `type="password"` にしているため、画面を見ただけでは値が見えません。ただし保存先の localStorage には、暗号化せずそのままの文字列で入っています。この端末のブラウザの開発者ツール(または端末を丸ごと不正に操作された場合)を使えば、値そのものを取り出せてしまいます。
- これは「バックエンドを持たない、1ファイルの個人アプリ」という構成上の制約で、コード側だけで根本的に直すことはできません(直そうとすると、ログイン・セッション管理を持つ本格的なサーバーが必要になり、この構成の単純さが失われます)。
- 現状の設計で成立している前提は「この端末を自分以外が触らない」ことです。次のような場合はご注意ください。
  - 家族共有の端末やPCでこのアプリを開く場合(ブラウザのプロファイルを分けるか、使い終わったらトークンを再発行することをおすすめします)。
  - 端末を売却・譲渡する場合(事前に「設定」タブでトークンを削除するか、Apps Script側でその値を無効化・再発行してください)。
- 個人の運動・食事記録以外(決済情報など)をこの仕組みで扱う用途には向いていません。

### その他

- ホーム画面用のアイコン画像(`apple-touch-icon`)は未設定です。好みの画像を用意して `<link rel="apple-touch-icon" href="icon.png">` をheadに追加すると、アイコンが見た目良くなります。
- デザイン(色・フォント)はai-diet-mvpのトーンに合わせています。調整したい場合は `<style>` 内のCSS変数(`--teal`, `--coral`, `--sand`, `--slate` など)を変更してください。
- 目標カロリー計算(BMR・基礎消費)はルールベースの計算式(Mifflin-St Jeor式)です。「🔍 AIで栄養を調べる」「🤖 AIのひとこと」の2つの機能だけ、設定した場合に限りGoogle Gemini/Groq APIに接続します(詳しくは冒頭の説明を参照)。医療的な正確性は保証されないため、実際の健康管理では専門家の助言も参考にしてください。
